# affinity/

> 语言：**简体中文** | [English](README.md)

提示词前缀亲和：记住哪个上游最近服务过哪些提示词前缀，并把持有最长匹配的
上游提升到候选列表头部。provider 的 prompt cache 按前缀预热——重复前缀打
到已持有它的上游，就省下了首次请求已付出的 prefill 工作。默认关闭：
非正 TTL 下 `NewIndex` 返回 nil，nil 索引在每个调用点都合法，关闭亲和无需
任何分支。

## Files

| File | 职责 |
| --- | --- |
| `affinity.go` | `Index`：每模型一棵前缀 trie；`Pick` 匹配请求的分块链并记录路由决策（miss 也记录——只记录命中的索引永远不会播种） |

## 机制

- 提示词文本（见 `pipeline.PromptText`）从位置零起切成固定的 128 字节块，
  每块独立哈希（FNV-1a 64）。固定分块不需要节点存文本、也不需要插入时的
  边分裂；两个提示词在相同边界上对齐，尾部不足一块的切片按原样哈希，因此
  一段对话在越过已记录请求的结尾继续时，至多损失一块的亲和度。超过 512 块
  的提示词只取头部——缓存复用集中在头部。
- trie 节点持有经由该前缀路由过的上游 ID。匹配沿分块链行走，逐层保留路由
  序最靠前的 eligible ID；最深命中获胜，行走止于首个节点缺失或不含任何
  eligible ID 的深度——只有路由已放行的 ID 才会参与比较，死亡或被排除的
  上游永远无法钉住流量。
- 决策在挑选时刻记录给将带头尝试的候选：miss 记录头部，下一次相同请求即可
  命中。记录是路由决策的回声，不是完成回执；失败的交换其条目原地保留，
  由下一次的 eligibility 过滤淘汰。
- 内存双重封顶：每模型的节点上限（放不下的记录直接跳过，退化为纯策略序）
  与新鲜度 TTL——写路径上的节流清扫执行过期，与 cache 模块的过期同一纪律。
  剪枝先走子节点，长共享前缀在其尾部扩展先过期时依然存活。

## Scope rules

- 索引只见字符串：模型名、提示词文本、上游 ID。handler 在路由的 eligibility
  闸门之后组装它，并同样作用于 fallback 模型——链与主模型走同一纪律。
- 提升会覆盖策略的头部选择：缓存温热支配策略所度量的延迟差；头部之后的
  顺序保持路由原序，failover 不受影响。
- 同一深度的平手按路由位置裁决，而非随机：两三个上游的规模下，确定性选择
  同时也是可测量的选择。
- 哈希碰撞会合并两条分块链，后果只是把请求路由到另一个同样服务该模型的上游
  ——永远不是正确性问题。
